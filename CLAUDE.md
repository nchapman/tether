# CLAUDE.md

Guidance for Claude Code agents working in this repo.

## What this is

Tether is a low-latency open-source remote desktop in Rust. Two binaries (`tether-host`, `tether-client`) and nine library crates in a Cargo workspace; pre-MVP. Linux↔Linux (VAAPI encode, PipeWire DMA-BUF capture, wgpu present) is the most exercised path and negotiates HEVC Main 4:4:4 at 8-bit (packed `XYUV`, `Yuv444DmaBuf`) and 10-bit (packed `XV30`, `Bgra2Xv30DmaBuf`). macOS host and client are wired end-to-end: ScreenCaptureKit → VideoToolbox encode (`encode_iosurface_frame`) and VideoToolbox decode → IOSurface → Metal → wgpu import for HEVC Main, Main10, and Main 4:4:4 8/10-bit. CGEvent input via `inject::enigo_backend`. **Windows host** (DXGI Desktop Duplication capture → `ID3D11VideoProcessor` BGRA→NV12/P010 → vendor-selected D3D11 encode: Intel→`hevc_qsv`, AMD→`hevc_amf`, NVIDIA→`hevc_nvenc`, Media Foundation fallback; unknown vendor → MF-only) and **Windows client** (D3D11VA decode → GPU-resident shared-handle export → native D3D11 render, no wgpu/Vulkan bridge) are wired and loopback-verified — 4:2:0 NV12 8-bit + P010 10-bit (Main10); no VP 4:4:4 path (rejected at construction + probe). Cross-device decode→present sync relies on handoff latency (validated on shared iGPUs; discrete GPUs may need a single shared device). **System-output audio is wired end-to-end on all three platforms** (`tether-audio`): per-platform capture (Linux PipeWire sink monitor via `stream.capture.sink`, macOS ScreenCaptureKit, Windows WASAPI loopback — which converts the render endpoint's pinned mix format to 48 kHz stereo f32 since loopback can't request a format) → libopus encode with PLC → `Datagram::Audio` (unreliable) → lock-free jitter ring with cap-and-drop playback → cpal cross-platform output. Negotiated host-authoritatively via the `tether.audio` hello extension, gated on `capture::is_supported()` + host `--no-audio`; no user-facing toggle yet (waits on user-prefs). See `docs/CODEC_CAPABILITIES.md` Windows layers. Toolchain pinned via `mise.toml` (rust 1.95); MSRV 1.85.

## Common commands

**First build / fresh clone:** run `make ffmpeg` once. `tether-codec` statically
links our own LGPL FFmpeg 8.1 from the `nchapman/tether-ffmpeg` releases (pinned
in `scripts/ffmpeg-version`); `scripts/fetch-ffmpeg.sh` downloads + checksum-verifies
the host artifact into `vendor/ffmpeg/` (gitignored) and `.cargo/ffmpeg-env.toml`
points rusty_ffmpeg at it. The `make` build/test targets fetch it automatically
(idempotent); a raw `cargo build` on a fresh clone fails with a pkg-config path
error until `make ffmpeg` has run. No system FFmpeg dev package is needed. There
is no software encoder in the LGPL build — see `crates/tether-codec/src/h264.rs`.

All wrapped by `make` (`make help`). Key targets:

- `make ffmpeg` — download + stage the pinned static FFmpeg for this host (idempotent)
- `make build` — `cargo build --workspace`
- `make test` — `cargo test --workspace --lib` (no hardware)
- `make test-hw` — `test-correctness` + `bench`; needs VAAPI + Vulkan
- `make test-correctness` — the `#[ignore]` hardware tests in `tether-codec`, `tether-render`, `tether-gpuconvert`
- `make bench` — `cargo test -p tether-codec --lib bench -- --ignored --nocapture --test-threads=1` (serial: parallel cells contend for the VAAPI device)
- `make probe` — VAAPI codec build availability
- `make clippy` — advisory
- `make release` — host + client release build
- `make ci` — the no-hardware checks CI runs (fmt, gating, warning-free build, test)
- `make package` — local Tauri installer bundle with the engines embedded as sidecars
- `make hooks` — install the git pre-commit hook (fmt + gating; run once per clone)

Single test: `cargo test -p <crate> <name>`. Hardware tests are `#[ignore = "requires …"]`; the message names the requirement.

## Architecture orientation

`docs/ARCHITECTURE.md` is the source of truth; `docs/CODEC_CAPABILITIES.md` holds the per-backend matrix. Read them before non-trivial changes. Load-bearing pieces:

- **`tether-protocol`** has zero I/O. Wire contract: control (bincode, reliable), input (reliable stream), and **all video — IDR keyframes and P-frames alike — on one unreliable FEC'd datagram channel** alongside cursor + audio datagrams (there is no reliable keyframe stream; a split transport let an IDR be overtaken by its dependent P-frames). Every frame goes through `FrameFragmenter::fragment(meta, body, datagram_budget)`: primaries split into independent Reed-Solomon FEC blocks (`VideoPacket::Parity`, ~20%, each block ≤ `FEC_MAX_PRIMARY_SHARDS = 212`) so large IDRs stay loss-protected (no no-FEC fallback); `shard_size` is derived per frame from the connection's `max_datagram_size` minus the encoded meta+header so every datagram fits the path MTU (the receiver re-derives the block layout from `fragment_count` + `fec_pct`). Receiver bounds (`MAX_FRAGMENTS_PER_FRAME = 4096`, `MAX_FRAME_BODY_BYTES`, `MAX_FEC_PCT`) reject malformed envelopes before allocation. Forward-compat: hello extension map (`tether.cap.*`, echo-to-accept), `ControlMessage::Extension`, `VideoFrameMetaEnvelope`.
- **Hot path is zero-copy.** Host: DMA-BUF → `tether-gpuconvert` (BGRA→NV12 into shared dma-buf, R8 Y + Rg8 UV at offsets) → `tether-codec::vaapi` → `FrameFragmenter` → `tether_session::PacedSender` (token-bucket on `Arc<AtomicU64>` bitrate) → QUIC datagrams (IDR + P alike). `drain_encoder` prepends extradata to every IDR for self-decodability. Capture frames carry optional `native_damage` (`SPA_META_VideoDamage` / `SCStreamFrameInfo.status`) so HashDamage short-circuits when idle. Client: `recv_datagram` → defragment with per-block FEC recovery → **`tether-decode::run::run_thread`** (callback-injected `request_idr` + `warnings`; concealment classified `Flush` → `Rebuild` → `Idr` gated by `Decoder::flush()`) → `vaExportSurfaceHandle` → `tether-render` imports both planes. Decoder→renderer handoff is `LatestFrame` (single-slot drop-oldest); `tether-render::present_policy` (`PresentPolicy`, `FrameAgeTracker`, pure `decide_present`) handles aged-frame skip with hysteresis.
- **Cross-platform additivity** via two type seams: `CapturedFrame::Gpu(GpuCapturedSource)` and `GpuEncoderFrame` are cfg-gated per variant (`DmaBuf` on Linux, `IOSurface` on macOS), so matches stay exhaustive and a third backend is a variant + module, not a refactor. Opaque `GpuResourceGuard` (re-exported as `GpuCapturedGuard` / `GpuFrameGuard`) hides backend lifetime types. macOS-host skips gpuconvert/`BridgeState` entirely — SCK hands NV12 IOSurfaces to VideoToolbox via `CVPixelBufferCreateWithIOSurface`, and the encode probe rejects non-4:2:0 profiles up front.
- **Four end-to-end invariants:** (1) clock sync via handshake-measured `MonoNanos` offset + per-fragment `HostFrameTiming` stamps; (2) `stream_epoch: u32` bumped on resolution/encoder restart, defragmenter drops cross-epoch fragments; (3) on-demand IDR via `ControlMessage::ForceIdr` coalesced through `AtomicBool` (GOP ~240, request-driven); (4) every IDR is self-decodable — `AV_CODEC_FLAG_GLOBAL_HEADER` puts SPS/PPS/VPS in `extradata` and `drain_encoder` prepends them to each keyframe.

## Conventions that aren't obvious from grep

- **`HostFrameTimingBuilder` is typestate.** Skipping a stage panics. New host-pipeline stages add a `should_panic` test for the skip case.
- **Wire round-trip first.** Every new protocol message gets a round-trip unit test in `tether-protocol/src/lib.rs#mod tests`. Tagged-enum additions also get a forward-compat probe (see `unknown_client_hello_variant_fails_decode`).
- **Hardware tests are `#[ignore]`, not deleted or runtime-skipped.** The ignore message names the requirement. Before claiming a new profile / chroma / bit-depth / fourcc works, a hardware test must take a real artifact through the chain you touched: `videotoolbox_round_trip_chroma_matrix` (macOS encode), `hevc_main444_dmabuf_roundtrip` / `hevc_main444_10bit_xv30_dmabuf_roundtrip` (Linux encode), `iosurface_zero_copy_roundtrip_*` (macOS renderer), or the Linux harness `tether-render/src/test_harness.rs` + `dmabuf_test.rs` driving `Gpu::new_headless` across `(capture × encode × surface)` dims. New cells are `RoundtripCase` literals + an assert; primary metric is geometric residual on `Fixture::CoordEncoded`, SSIM + Y-PSNR are the catch-net. Failures dump PNGs + `metrics.txt` to `target/roundtrip-diagnostics/<case>/` (`TETHER_DIAGNOSTICS_DIR` override). Probe-pass is half-credit — the renderer side runs on parallel tables and bugs (R16Unorm feature opt-in, `'x420'` fourcc, encoder/decoder table drift) historically live in code with no hardware coverage. Any knob that may silently no-op (e.g. VAAPI per-frame options) gets a SKIP-with-diagnostic test (`vaapi_intra_refresh_round_trip`, `vaapi_min_qp_floor_reduces_bitstream`, `vaapi_bitrate_retune_changes_bitstream_size`) so the negative is recorded. Driver SKIPs and per-backend matrices live in `docs/CODEC_CAPABILITIES.md`.
- **Three-layer bisect tests** (`tether-scaler/tests/hardware.rs::matches_reference_coord_encoded_left_edge`, `tether-gpuconvert/tests/scaler_roundtrip.rs::bgra_dmabuf_roundtrip_*` and `::imported_bgra_then_scaler_*`) split harness "somewhere in the host pipeline" verdicts into scaler / dma-buf round-trip / scaler-on-dma-buf without re-running the full chain.
- **Cross-table consistency belongs in unit tests.** `metal.rs::import_iosurface_textures`, `videotoolbox/probe.rs::expected_iosurface_fourccs`, `videotoolbox/encoder.rs::iosurface_fourcc_matches`, `capture::macos::sck_pixel_format_for_profile` all encode the same chroma/bit-depth → fourcc relation; a no-hardware unit test asserts they agree.
- **End-to-end session loopback** runs in default `cargo test` via `tether_transport::test_support` (`DuplexControlChannel`, `DuplexVideoChannel`, `DuplexInputChannel`, `LossyChannel`) + `tether_decode::test_support::FakeDecoder`. Integration tests under `crates/tether-session/tests/` cover video send/recv, input, decoder-thread restart under loss; fragmenter is proptested in `crates/tether-protocol/tests/fragmenter_property.rs`.
- **Hard requirement on hardware codecs.** SW H264 is `cfg(test)`-gated. The probe returns `NoHardwareCodec` with actionable diagnostics rather than falling back silently.
- **NV12 export is pinned to `DRM_FORMAT_MOD_LINEAR`.** Tiled modifiers have no portable shared-allocation contract that VAAPI's DRM_PRIME importer honours. Capture side advertises whatever the GPU importer consumes; export is LINEAR-only. See the comment in `tether-gpuconvert` before "optimizing."
- **DMA-BUF luma row pitch is force-aligned at the exporter.** `shared_nv12.rs`, `shared_p010.rs`, `shared_yuv444.rs` align to 64-byte pitch + 16-row height; `shared_xv30.rs` to 128-byte pitch + 32 rows (Intel HEVC 4:4:4 32×32 CTU × 4 B/px). Vulkan image at aligned dims, compute dispatch covers only the visible region, VAAPI crops via declared width. Without this, libva-intel-driver mis-reads non-aligned widths (e.g. 2160 px on HiDPI 2×): hardware-side pitch alignment, no upstream fix expected. RADV/NVK already report ≥128-byte pitch. Structural regression: `convert_reports_64_aligned_y_stride_at_unaligned_width` in `crates/tether-gpuconvert/src/nv12_dmabuf.rs`.
- **Bridge init failures mid-session are fatal.** Startup probe `tether_gpuconvert::importable_dmabuf_modifiers` verifies wgpu+Vulkan+features before PipeWire advertises DMA-BUF. Runtime failure = device-loss/OOM — exit with `Goodbye(InternalError)`, don't silently drop frames. Same on the encoder lazy-init path: if `probe_encoder` succeeds at handshake (128×128) but real-dim construction fails, send `Goodbye` before exiting.
- **Video profile negotiation is host-authoritative.** Client advertises decode caps via `tether.cap.video.decode-profiles`; host intersects against `tether_probe::host_encode_profiles()` and picks from `tether_probe::PROFILE_PREFERENCE` (HEVC 4:4:4 10-bit → HEVC 4:4:4 8-bit → HEVC Main10 → HEVC Main → H.264 4:2:0 floor). Result echoed in `tether.cap.video.encode-profile`. `tether_probe::host_supported_profiles()` round-trips every profile through the production chain; `SupportStatus::Unsupported` carries a `PipelineStage` tag. Renderer dispatches on `RenderLayout` (Biplanar8 / Biplanar16 / PackedXYUV) per chroma + bit_depth + platform; `gpu/import.rs:53` documents the unverified XV30-vs-biplanar-16 driver split for Linux 4:4:4 10-bit decode.
- **VAAPI per-frame encoder knobs have a verified-negative ceiling.** intra_refresh, qmin, live `bit_rate` retune all dead-end at FFmpeg's `vaapi_encode.c::vaapi_encode_init_rate_control` / `init_picture_params` building the misc buffer once at `init()`. `VaapiEncoder::supports_changing_bitrate` is deliberately `false`; ABR is disabled on VAAPI. Before adding a new VAAPI AVOption, grep `vaapi_encode.c` for `init_rate_control` / `init_picture_params` / `vaapi_encode_make_misc_param_buffer` and confirm the field is re-read post-open — if not, it's a silent no-op regardless of `unused_avoptions()`.
- **No scaffolding for hypothetical futures.** Wire variants, signal types, controller fields, envelope versions only land alongside an end-to-end behaviour that exercises them. No "phase 2" comments, placeholder match arms, or `#[allow(dead_code)]` "will use later" fields. Re-add cleanly when the consuming feature ships.
- **Input + capture seams.** `tether_capture::CaptureHandle { rx, target_fps: Arc<AtomicU32> }` is every backend's `start()` return; the atomic is the live-retune seam. Relative mouse rides `InputEventKind::RelativeMouseMove { dx: i16, dy: i16, modifiers }` with `ControlMessage::SetCursorMode`; winit f64 deltas accumulate sub-pixel residue through `tether-render::relative_mouse::SubPixelAccum`; injection clamps to ±1000 px/event. Host rate-limits `ForceIdr` + `RequestRecovery` to one per 250 ms.
- **wgpu is pinned to a trunk SHA via workspace `[patch.crates-io]`** because `texture_from_dmabuf_fd` isn't released. All wgpu sub-crates (`wgpu-core`, `wgpu-hal`, `wgpu-types`, `naga`) move together. Drop the pin when wgpu cuts a release with the API.
- **Transport role traits in `tether-transport`.** `ControlChannel`, `InputChannel`, `VideoChannel`, `ConnectionInfo` in `tether-transport::channel`; concrete `Connection` impls all four. `tether-session` takes `Arc<dyn ControlChannel>` so post-QUIC handshake is loopback-testable. Handshake split across `recv_client_hello` (returns `(ClientHello, t1)`) + `send_server_hello` (stamps `t0_echo` / `t1` / `t2` immediately before write) keeps clock-sync in the wire layer and negotiation policy in `HostSession::accept`. `HostHandshake` → `ClientHelloReceived` typestate makes double-send and send-before-recv uncompilable.

## Testing matrix

See `docs/TESTING.md` for per-crate counts and infrastructure. Default CI is `cargo build --workspace --all-targets && cargo test --workspace`; the build must stay warning-free. Hardware runs add `-- --ignored`. Clippy is a blocking gate (`cargo clippy --workspace --all-targets -- -D warnings`, plus the excluded shell); intentional numeric casts are suppressed with scoped `#[allow]` + justification, not by disabling the workspace cast lints. CI/CD lives in `.github/workflows/` (`ci.yml` on push/PR across Linux/macOS/Windows; `release.yml` on `v*` tags → Tauri-bundled installers + signed updater manifest to GitHub Releases) with shared setup in `.github/actions/setup`; `make ci` reproduces the no-hardware checks locally. Release + packaging flow is documented in `docs/RELEASING.md`.
